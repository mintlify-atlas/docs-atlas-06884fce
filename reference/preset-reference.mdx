## How Presets Work

Presets are **starting points, not verdicts**. Every preset ships as a JSON file in the `Presets/` directory. Importing a preset fills in the controls — nothing is written until you press Apply (TUI / Windows GUI) or the import completes (CLI). Adjust anything you disagree with before committing.

### How to apply a preset

<Tabs>
  <Tab title="CLI (Linux / macOS)">
    ```bash
    sudo python3 slimbrave-linux.py --import "./Presets/Maximum Privacy Preset.json"
    sudo python3 slimbrave-mac.py   --import "./Presets/Balanced Privacy Preset.json"
    ```
  </Tab>
  <Tab title="TUI (Linux / macOS)">
    Press **Import** in the button row at the bottom of the TUI, enter the path to the preset file, and press Enter. The controls update to reflect the preset. Press **Apply** to write the policy.
  </Tab>
  <Tab title="Windows GUI">
    Click the preset's card in the Presets section. Review the populated controls. Press **Apply Settings** to write the policies to the registry. Nothing is committed until that button is pressed.
  </Tab>
</Tabs>

### Shared rules across all presets

- **None** of the presets sets "Disable Safe Browsing" — Brave proxies Safe Browsing lookups through its own servers, so disabling the protection costs phishing and malware interstitials for no privacy gain. The toggle remains available manually.
- **None** of the presets sets "Allow Permissive Referrers" (`DefaultBraveReferrersSetting: 1`), which would make referrer weakening global as managed policy.
- **None** of the presets sets the mutually-exclusive Shields overrides ("Disable Brave Shields" and "Force Shields On") simultaneously.
- Every preset **except Strict Parental Controls** sets `BackgroundModeEnabled: false` (Windows/Linux only). macOS does not have this policy key; on macOS the key is silently skipped and the rest of the preset applies unchanged.

### DNS

Not set (unmanaged). The preset deliberately leaves DNS mode to the user's preference — see the DNS section of the TUI or pass `--doh-templates` on the CLI.

### Not set (intentionally)

- `DefaultWebUsbGuardSetting`, `DefaultSerialGuardSetting`, `DefaultWebHidGuardSetting`, `DefaultLocalFontsSetting`, `DefaultWindowManagementSetting` — blocking these breaks hardware wallets, in-browser firmware flashers, and some security keys. Set them to Block manually for the full lockdown.
- `SafeBrowsingEnabled` — disabling Safe Browsing is a security downgrade; excluded from every preset.
- `IncognitoModeAvailability: 2` — no longer forces incognito-only browsing; `DefaultBraveRemember1PStorageSetting: 2` (forget-on-close storage) covers the privacy goal without the login-breaking side effects.

<Accordion title="Strict Parental Controls Preset">

**Best for:** Parents, schools, or workplaces that need restricted browsing with content filtering, no incognito or guest mode, and no extension installs.

<Warning>
  **SafeSites is a Google callout.** `SafeSitesFilterBehavior: 1` sends every URL the browser navigates to — including URLs loaded inside frames — to Google's Safe Search API for classification. This is a remote lookup, not a local blocklist. If that trade-off is not acceptable, untick "Filter Adult Content (SafeSites)" and rely on the DNS filter alone.
</Warning>

<Warning>
  **The DNS template requires network access to `family.cloudflare-dns.com`.** This preset uses `DnsMode: custom` with `DnsTemplates: https://family.cloudflare-dns.com/dns-query`. Chromium's `custom` mode is a secure DoH mode: DNS lookups go over HTTPS only and are never retried against the system resolver. If that endpoint is blocked or unreachable — captive-portal Wi-Fi, some corporate or school networks — **nothing resolves at all** until you change the DNS mode or reset the policy. Point the template at a resolver you know works on your network.
</Warning>

### DNS

### What this preset cannot give you

Origin also **compiles features out of the binary** and ships with metrics telemetry removed at build time. Policy keys can't shrink a binary. For the closest match on standard Brave, also enable "Disable Metrics Reporting" (`MetricsReportingEnabled: false`) — Origin builds don't report metrics at all.

Origin's 16th policy (`PsstEnabled`) is not dispatched by any stable Brave build and its feature flag is off everywhere, so it is not included here — a switch that does nothing is worse than no switch.

### On an actual Brave Origin install (Linux)

Thirteen of the fifteen keys name features Origin removes at build time. On a machine whose only Brave is Origin, the import reports those 13 as built-in and leaves them unmanaged, and ticks the other two — `BraveP3AEnabled` and `BraveStatsPingEnabled` — which Origin already defaults off; the managed value pins them so they can't be re-enabled from Settings.
